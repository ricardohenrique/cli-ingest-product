# Productsup – Live Coding Interview Preparation

## Overview

This interview is based on the take-home assignment I already submitted.

The goal is **not** to test how quickly I can understand a new codebase, but rather how I think about extending, improving, and maintaining software that I already know.

### Logistics

* Duration: 60 minutes
* Format: Screen sharing
* Use my own editor and environment
* Have the project running before the interview starts

---

# Interview Structure

## 0–10 min — Introduction & Project Walkthrough

Be prepared to explain:

* What the application does
* Main architectural decisions
* Trade-offs made during implementation
* What I would improve with more time
* Known limitations

### Good talking points

* Why I chose the current structure
* Why I chose specific frameworks/libraries
* How I approached testing
* What assumptions I made

---

## 10–50 min — Pair Programming Extension

Expected tasks:

* Add a small feature
* Handle an edge case
* Refactor existing code
* Improve maintainability
* Extend existing functionality

---

# What They're Evaluating

## Communication

Explain reasoning continuously.

Don't code silently.

Examples:

* Why you're changing something
* Why you're not changing something
* Why you're choosing one approach over another

---

## Clarifying Questions

Ask questions early.

Examples:

* What should happen in this edge case?
* Is backward compatibility important?
* Should we optimize for simplicity or extensibility?

---

## Judgment

They explicitly care about:

* When you push back
* When you adapt
* When you refactor
* When you avoid refactoring

Good engineers don't always change everything.
